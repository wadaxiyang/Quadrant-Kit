## Input, scrolling and lifecycle

Interaction raw: `target/interaction-perf/20260910T022523142072Z/result.json`.
Six scenes, three independent alternating pairs each, 200 transactions per process:
36 processes and 7,200 software frames. Two-field transactions focus, press End,
insert and delete in each field; long text is restored exactly after all samples.
WindowEvent key/focus and wheel input is real native-control dispatch, but not OS
IME composition. Both software-frame p95 and per-sample dispatch-plus-frame p95
increments pass max(1 ms, 10% of native). The latter derived results are retained
in `target/p7-interaction-total.json`; long text totals are 22.1985 / 22.6297 ms.
These are multi-event transactions, not evidence of universal 60 fps.

Cumulative list delegate creations match native: 183 for 100 rows and 817 for
both 1,000 and 10,000 rows in every run. Cumulative creation includes re-creation
while reversing scroll; it is not simultaneous residency or a public layout count.

Gallery raw: `target/gallery-lifecycle/20260910T023606419430Z/result.json`.
Three normal Release hosts each complete 100 round trips / 200 transitions among
the 32 destinations, then 60.1s idle. Snapshot p95 is 13.8283, 13.9382, 13.7496 ms;
maxima 16.2119, 20.3375, 18.5793 ms. A separate temporary instrumented build inserts
page-root timers: all 200 checks see exactly one selected active page. Instrumented
values are not combined with normal timing. The host uses current Gallery UI,
catalog and navigation but omits its OS chrome adapter.

All four Gallery idle intervals record 0 CPU seconds; private memory falls during
idle. This does **not** prove leak freedom: late home-page memory still fluctuates,
with positive fitted slopes of about 1,794 / 3,030 / 9,597 bytes per round trip and

12.309 MiB. Allocation caches, route history and resource lifetimes are not separated
by this probe; a bounded active-page result cannot close a universal flat-memory
gate. Long-duration retention diagnosis remains backlog, without inventing a leak
or modifying budgets to hide it.

## Acceptance limits

PASS applies only to the named measurements and current behavior. Actual present,
cold-start cache isolation, GPU memory, exact idle redraws, actual IME composition,
screen reader, physical monitor/DPI moves and macOS execution are NOT_RUN here.
Gallery long-term flat-memory acceptance is unresolved. The unmatched Toast row
remains BLOCKED even after the separately matched hidden-state attribution passes.
No new production optimization is justified by the matched measurements, so no
controls, ownership semantics or accessibility are removed. Linux/MSRV and the
post-commit source package/independent consumer/incremental checks are recorded
separately in P8. This is scoped completion with explicit release limits, not full
WinUI 3 equivalence or authorization to publish, tag, push or update Tasks.
