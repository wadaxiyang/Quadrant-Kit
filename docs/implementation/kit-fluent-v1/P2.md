## Current API and implementation review

Before migration, FluentButton drew its own border/background/text/icon and owned
three command paths: TouchArea, FocusScope key handling and an accessible default
action. It also exposed redundant accent/show_icon and synthetic preview inputs.
The captured before image and P0 source/performance evidence retain that history;
no historical implementation or compatibility alias is retained in current Kit.

The sole current implementation contains a visible public std Button. Pointer,
keyboard, focus, disabled visuals, icons and 150ms Fluent transitions are native.
One enabled-guarded native clicked forwarding path emits the Kit command; no
custom TouchArea, FocusScope, keyboard handler, accessible action or Kit animation.
The Rectangle container uses native content minimums as its default dimensions.
An empty button defaults to 32×32 logical pixels; callers can explicitly size it.

Danger uses a neutral native surface, including when primary is also true, plus
a passive red outline 2px outside the control. The outline does not intercept
input or add an accessible node. Disabled outlines use a neutral tone. This is
an intentional replacement for the old red fill, not a hidden native proxy or a
shared Palette override. Host theme/Palette/font initialization remains required.

| API category | Reviewed P2 change |
|---|---|
| Removed inputs | show_icon, accent, preview_hover, preview_pressed, preview_focus |
| Added input | accessible_name: optional native accessible label; empty falls back to text |
| Added outputs | has-focus and pressed: read-only native state |
| Preserved declarations | text, icon, primary, danger, enabled, clicked; Rectangle base and facade name |
| Behavior/default changes | Image presence controls icon visibility; native 20px tinted icon; native sizing/font/states; danger chooses neutral surface and outline |
| Current snapshot | 35 exports, 238 declared properties, 20 callbacks; only FluentButton differs from P1 |
